## 商品の第一案

無料Webで触れる → 好きな遊びを見つける → もっと遊びたい人が一度の購入で完全版へ。

無料でも作品として気持ちよく遊べる。最初の起動に登録・決済を要求せず、基本の描画・音・操作品質を揃える。無料の終わりを時間切れで作らず、コースの区切りで完全版を案内する。購入後に何が増えるかを具体的に見せる。

最初の商品は一つの「完全版」を第一候補とする。主な販売価値は全コースと全モードの深さ。継続的な追加配信を約束する契約を先に作る必要はない。将来の新コースや展示向け提供は、需要が見えてから別に検討する。

### 無料／完全版の範囲案

まだゲームの制限を実装していない。身内向けの承認版を、この表で突然制限しない。正式な無料版は別の配信用ビルドとして準備する。

| 遊び | 無料の入口案 | 買い切り完全版案 |
|---|---|---|
| はじめて・はじめる | 全部 | 同じ体験 |
| エンドレス | 回数制限なし | 同じ体験 |
| ひとふで | まず3ホール＋今日のホール | 全18ホール・前半／後半／全ラウンドとスコアカード |
| 道 | 第1章の4面 | 全4章16面 |
| カーリング | やさしいCPUとの短い試合 | 全難度・通常の試合・同じ端末で二人 |
| スコア | 最初の面を繰り返し遊べる | 全8面 |
| 自由 | 気持ちよい既定配置を触る | 数・色・粘度・慣性・摩擦等を自在に調整 |

今日のホールを無料にすると再訪の入口になる。無料版で配れる挑戦状は無料で遊べるホールに限定し、受け取った相手がそのまま挑戦できるようにする。完全版ホールの挑戦状を無料で一面だけ開く方式は、販売ルールを決めてから検討する。

有料案内はメニューと、無料コースを終えたあとの自然な区切りに置く。文案は「続きをひらく」「全18ホール、四つの章、すべての遊び方」。価格・内容・買い切りであることを購入前に明記する。価格は未決定で、購入意向と無料範囲を確かめてから仮価格を置く。

## 販売経路

いまのスマホ中心の体験を活かす第一候補は、無料Webと同じ場所で完全版を購入し、続けて遊べる形。独立したWebサービスに購入と復元の仕組みを持たせる必要があり、現行の静的配信だけでは成立しない。販売サービスの対応地域・ゲーム販売可否・手数料・復元方法を比較して選ぶ。

| 経路 | PURAとの関係 | 確認した条件と判断 |
|---|---|---|
| Web完全版 | スマホ／PCとも無料の体験から連続して進める第一候補 | 購入確認と復元をサーバー側で扱う。無料開始にアカウントは不要。購入証明の復元とプレイ記録の同期は別機能 |
| itch.io | 無料の入口と支援、PC向けダウンロード販売の候補 | HTML5の埋め込み版の支払いは支援金。買い切り販売はDownloadable扱い。ブラウザ完全版の購入制限がそのまま提供されるとは扱わない [公式](https://itch.io/docs/creators/html5#can-i-take-payments-with-my-html5-game) |
| Steam | PC向け完全版を販売する次の候補 | 実行可能なPC版のパッケージと端末検証が必要。1製品US$100、最初の数タイトルは支払から30日・Coming Soon最低2週間。販売開始日を先に約束しない [公式](https://partner.steamgames.com/steamdirect) |
| App Store／Google Play | スマホで購入・再インストールしやすい完全版の候補 | アプリ化・実機検証・審査が必要。Appleは年間US$99、Play登録は一度US$25。アプリ内解放はストアの仕組みを基本とし地域別の規則を確認する [Apple登録](https://developer.apple.com/programs/enroll/)・[Apple課金](https://developer.apple.com/app-store/review/guidelines/#in-app-purchase)・[Play登録](https://support.google.com/googleplay/android-developer/answer/6112435) |

GitHub Pagesには商取引を主目的にしたサイト等の利用制限がある。現在の身内試遊から、そのまま課金サービスへ拡張しない。無料の展示／試遊と販売のどちらに使うかを区別し、販売機能は対応する配信先へ置く。[GitHubの公式条件](https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features#github-pages)。寄付やクラウドファンディングへのリンクは許される場合があり、商用活動すべてが禁止とは解釈しない。

## ローンチまでの順序と判断点

| 順 | 仕事 | 確認できたら次へ進む |
|---|---|---|
| 1 | 無料／完全版の範囲と販売経路を決める。上の表を触れるメニュー案にする | 無料だけでも満足でき、完全版で何が増えるか伝わる。価格と配信方法の整合がある |
| 2 | 初めての人8〜12人ほどに、説明なしで試してもらう。Androidを含め端末を記録 | 操作を発見できるか、どこで迷うか、翌日また遊ぶかを把握。ゲーム進行を止める不具合を解消 |
| 3 | 購入を試す前に、無料版／完全版を別ビルドで確認。購入・解放・復元・返金後の扱いをテスト環境で通す | 直接URLや旧モードの入口も同じ販売範囲。ブラウザ設定だけを購入証明にしない。通信が失敗しても無料部分を遊べる |
| 4 | 音楽と依存素材の利用根拠、保存移行、問い合わせ先、商品説明・規約等を揃える | 利用根拠と対象環境を記録。移行で身内のベスト記録を失わない手段がある |
| 5 | 実ゲームの短い動画・スクリーンショット・日本語商品説明を作る。海外販売先を選ぶなら英語表示も整える | 動画から触りたいと思えること。説明と実際の無料／有料範囲が一致 |
| 6 | 小さく一般公開し、遊び始め・再訪・完全版への関心・購入を観測して調整 | 日付・価格・販売範囲・公開先を最終確定した上でローンチ。数字を見て無料範囲や購入導線を改善 |

上記人数は、迷いや不具合を見つけるための小規模テストの目安。需要や収益性を統計的に証明する人数ではない。予想売上や公開日はまだ置かない。

### 初見テストの台本

渡す言葉は「このゲームを、好きなように触ってみてください」。操作を先に説明せず、手助けしたところは記録する。

1. 端末／OS／ブラウザ、初回かどうか、最初の表示から最初の操作まで。
2. はじめてで止まる場所、空いた床から引く操作が伝わるか、自分で別モードへ行けるか。
3. 自由に10分ほど遊んで、どのモードに留まるか。音・カクつき・画面スクロール・中断復帰の問題。
4. 終了後に「何がよかったか」「また開くなら何をするか」「どこまで無料だと思ったか」「完全版の何に魅力を感じるか」を聞く。
5. 翌日以降の再訪を任意で尋ねる。購入意向の回答と実購入は区別する。

まず表計算等の手動記録でよい。公開後は、遊び始めた数・再訪・モード別の利用・有料案内を開いた数・購入完了を追う。評価尺度はPURA自身の結果から決め、根拠のない「合格転換率」を置かない。計測の実装時にデータ項目・利用目的を決める。

## 製品化で残る具体的な仕事

- **保存と移行**: 今は同じブラウザのlocalStorage。別ドメインへ移しても自動では移らない。書き出し／読み込み等の移行方法を準備し、購入復元とプレイ記録の移行を別々にテストする。
- **購入権利**: Web版では決済結果の検証・再送／重複イベント・復元・返金後の扱いをサーバー側で管理する。無料デモは単独で動く形にし、決済用の秘密情報を配信ファイルへ含めない。公開ソースの再利用範囲と製品の利用条件も整理する。
- **オフラインと復帰**: manifestによるホーム画面追加は実装済み。オフラインで起動できる保証は未実装。初回読み込み・保存が使えない状態・再起動・画面回転・音の復帰・WebGLの再開を対象環境で確認する。
- **音楽**: 「The White Basin」はGemini生成との記録があるが、生成時の機能／利用条件の根拠は未収録。取得元と生成時の条件を確認し、ゲームへの組み込み／有料販売に使える根拠を保存する。音楽生成のヘルプだけでは商用利用の確認済みとしない。[Google公式ヘルプ](https://support.google.com/gemini/answer/16901237?hl=en)
- **対象環境**: 既存のiPhone実測を活かし、Android Chrome・iOS Safari・PCの対象ブラウザを現在の製品構成で確認。SNS内ブラウザは別枠で確認し、公開ページで対応範囲を明記する。
