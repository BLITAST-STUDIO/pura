# 電波がなくても遊べる（2026-10-02）

ユーザー「３もやりましょう」（電波がなくても遊べるように）。作業ブランチ `feat/offline`（`main` から）。これまで、ホーム画面に追加しても毎回ネットから読み込んでいた（`LAUNCH_PLAN.md` の「オフラインで起動できる保証は未実装」）。

## しくみ

- ビルドのたびに `dist/sw.js`（サービスワーカー）を自動で書き出す（`vite.config.ts` の `offlineWorker`、中身は `src/offline-sw.ts`）。ゲーム本体の全ファイル（約53個）と、音楽（2.7MB、取れなくても入れ替えは失敗にしない）を端末に保存する。全体で約5MB（圧縮した本体は約0.4MB）。
- **版は全ファイルの内容から決まる**（保存の名前に入る）ので、配信するたびに新しい保存になる。更新のし忘れがない。
- 開くとき: どの画面も、保存した `index.html` から（画面は住所の `?play=...` で決まるため）。画像・音・プログラムは保存したものから。保存にないものと、`build-info.json`・`sw.js` はネットから。
- 初回: ゲームが立ち上がったあとに、裏で保存する（初回の読み込みを遅くしない）。

## 古い版が居座らないための決まり（いちばん気をつけたところ）

- 新しい版は裏で用意して**待たせる**。入れ替えは、**開いた直後（12秒以内）で、まだ何もさわっていないときだけ**、画面が自分で頼んで入れ替え、一度だけ読み込み直す。遊んでいる最中に入れ替えることは決してない。
- さわったあとに来た新しい版は、その訪問が終わるまで待つ。閉じて開き直したとき（古い版を使う画面が一つもないとき）に有効になる。
- 古い保存は、新しい版が有効になったときに消える。保存の名前は、身内版（`pura-stable-`）と試作版（`pura-next-`）で別で、お互いの保存は消さない。身内版のワーカーは `/next/` の住所に触らず、試作版は `/next/` の中だけを担当する（それぞれ自分の `sw.js`）。
- 逃げ道: `?nosw=1` を付けて開くと、保存を全部消し、ワーカーを外し、その端末ではそのまま外れた状態になる（`?nosw=0` で戻る）。
- 配布用のZIP（itch）には入れない（`VITE_NO_SW=1`）。開発サーバーでも動かさない。

## 検証

- 型検査・208テスト（以前の数に offline のテスト6件）（保存する・しないファイルの振り分け、版が順序に依らず中身で変わる、ワーカーの実コードを偽のブラウザで: 立ち上げで全部保存・ゲームのファイルが取れなければ失敗して後で再試行・音楽は任意、どの画面も同じ index から、試作版や他サイトや GET 以外には触らない、試作版は自分の範囲と自分の名前の保存だけ、新しい版に替わるのは「頼まれたとき」だけ、頼むのは「開いた直後・操作前・古い版の画面があるとき」だけ）。
- 実ブラウザ（`scripts/check-offline.mjs`）: 一度開いて保存（54ファイル）→ **サーバーを止めて**（本当に電波なしにして）全10の入口（はじめる・ひとふで6番・道・カーリング・エンドレス・自由・スコア・元祖・自作ひとふで・はじめて）が起動、音楽ファイル（2.7MB）も取り出せる、`build-info.json` はネットなので失敗（正しい）。新しい版（別フォルダから配った2つ目のビルドで）: 開いたまま更新を確認させると、操作前なら自動で入れ替わって読み込み直し（保存は1つに）、操作後は新しい版が用意されても訪問が終わるまで待ち（保存は2つ）、いったん離れて戻ると新しい版（保存は1つ）。`?nosw=1` で全部消え、読み込み直しても外れたまま、`?nosw=0` で戻る。
- 未確認: 実機（iPhone のホーム画面アプリ、機内モード）、ストレージの容量が足りないとき、とても古いブラウザ。**身内版にはまだ出していない（試作版で評価してから）。**

## 確認の作りで直したこと

- 確認用スクリプト `scripts/check-offline.mjs` は、サーバーを止める処理で2度つまずいた（起動コマンドの形が違うと止まらない、ポートの接続者であるブラウザまで止めてしまう）。いまは「待ち受けているサーバーだけ」をポートで止める。
- 最初の更新の確認は、アプリを閉じて開き直す作りで、古い版を使う画面が一つもないために新しい版がすぐ有効になり、「操作前の入れ替え」も「操作後は待つ」も試せていなかった。いまは開いたまま更新を確認させる形で、2つの動きを別々に確かめている。
