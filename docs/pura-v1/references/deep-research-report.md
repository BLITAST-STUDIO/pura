# PURA FLOW「一滴のリアリティ」を極限まで高めるための研究レポート

## 研究結論

PURA FLOWで最初に追求すべき「一滴のリアリティ」は、**シェーダーをさらに豪華にすることだけでは到達できません**。

人間は液体らしさを、静止した色や透明度だけではなく、**輪郭がどう変形するか、動いたときに背景像がどう歪むか、その歪みが形状変化とどう同期するか、揺れがどの周期で減衰するか**といった時間方向の情報から強く判断します。実際、Kawabeらは、動的な画像変形だけから透明な液体を知覚できることを示し、別の研究では透明物体の弾性判断が輪郭運動と光学的変形のパターンに依存することを報告しています。液体については、静止画の形状だけでも材質判断の手掛かりになることが示されています。citeturn17search0turn17search2turn17search3

したがって、PURA FLOWで狙うべきものは、

> **形が液体らしく動き、その形によって光も正しく動き、そのすべてが指の動きに即座に因果的につながっている状態**

です。

今回いただいた現状の「ONE DROP, IN MOTION」の画面を静止画として見る限り、**アートディレクションはかなり良いところまで来ています**。暗いUIと白い盤面、抑えたシアン、透明感、ハイライトの整理、製品写真のような見せ方は「大人向けの高級なデジタルトイ」という方向に合っています。

一方、静止画だけを見ると、現在の一滴はまだ部分的に**「美しいガラス球／透明アクリル」**としても読めます。

これは失敗ではありません。

むしろ次の開発段階がはっきりしています。

**これ以上“ガラスを綺麗にする”より、“液体であることを動きで証明する”段階です。**

そして、もう一つ非常に重要な結論があります。

PURA FLOWの物体は、**純粋な「水」を物理的に再現しない方がよい**です。

実際の液滴は基板との濡れ性や接触線の摩擦・ピン止めの影響を受けます。接触線には動きを妨げる力があり、その挙動は接触時間や移動速度にも依存します。また、表面状態によってはstick-slip的な動きも起こります。つまり、普通の水滴を普通の平面に置いたものは、PURAが必要とする「カーリングの石のようにスーッと滑る一塊」とは必ずしも一致しません。citeturn19academia18turn19search0

そこでPURA FLOWでは、

> **水の光学**
>
> ＋  
> **高い表面張力を感じるまとまり**
>
> ＋  
> **ごく軽いゼリー的弾性**
>
> ＋  
> **極端に濡れにくい表面上での滑走**
>
> ＋  
> **ゲームとして気持ちよい融合性**

を組み合わせた、**架空だが一貫した「PURA Fluid」**を設計するのがよいでしょう。

完全に現実の水を再現するのではなく、

**「現実にありそうなのに、触ったことがない最高に気持ちいい物質」**

を作る。

私はこれをPURA FLOWの物理・映像設計の中心思想にすることを強く勧めます。

## PURA FLOWが目指すべき「本物感」の正体

リアリティを一つの数値として考えない方がよいです。

PURA FLOWの場合、少なくとも以下の六つが同時に整ったときに、ユーザーは「本当にそこに物がある」と感じやすくなります。

| 層 | ユーザーが無意識に見ているもの | PURA FLOWでの意味 |
|---|---|---|
| **形** | 丸さ、潰れ、接地、体積 | 水滴なのか、硬い球なのか |
| **運動** | 慣性、伸び、遅れ、揺れ、減衰 | 重さ・粘度・弾性を感じる |
| **接触** | 床との密着、滑り出し、壁衝突 | 本当に床の上に存在するか |
| **光学** | 屈折、反射、厚みによる色 | ガラス、水、ゼリーの材質感 |
| **因果** | 指→変形→移動の時間関係 | 自分が触っているという感覚 |
| **融合** | 接触→くびれ→一体化→余韻 | PURA固有の最大の報酬 |

仮想3D物体について、実際の材質情報がなくても形状だけから人が柔らかさをかなり一貫して判断できるという研究があります。つまり、**「柔らかそうな形」と「柔らかそうな動き」は、物理モデル内部の数値以上に重要な知覚情報**です。citeturn22search1turn22search9

透明物体の場合はさらに特殊で、輪郭だけではなく、**透明体を通して見える背景の動的変形**そのものが材質知覚に寄与します。PURAでは、これは極めて都合のよい性質です。盤面にうっすら模様や照明勾配を置き、雫が動くたびにそれが曲がれば、「透明度を上げた」以上の液体感を作れます。citeturn17search0turn17search3

### 「PURA Fluid」の暫定的な材質人格

これは研究値ではなく、研究結果からPURA向けに導いた**設計仮説**です。

| 物性 | PURAで狙う方向 | 理由 |
|---|---|---|
| 表面張力感 | **高め** | 一塊としてまとまり、融合後に丸へ戻ろうとする |
| 粘性 | **低〜中程度** | スライムほど鈍くせず、水より余韻を見せやすくする |
| 弾性 | **弱〜中程度** | 「ぷるん」は出すがゴムボールにはしない |
| 床への濡れ | **非常に弱い** | 接地しながらも美しく滑走させる |
| 接触摩擦 | **かなり低い** | カーリング的な滑走を成立させる |
| 慣性 | **明確に感じる** | 指を離しても移動が続く |
| 同色融合性 | **現実より強い** | 接触したらゲームとして確実に融合させる |
| 光学 | **水寄り＋色吸収** | ガラス玉ではなく「色のある液体」にする |
| 揺れ | **短く上質** | 長時間ぷるぷるして玩具っぽくしない |
| 余韻 | **一度大きく、数回小さく** | 重量感と快感を両立する |

「弾力性を高くすればリアルになる」ではありません。

本当の液滴の振動は、表面張力による復元と粘性などによる散逸が組み合わさり、さらに固体面上では濡れ性・接触線の状態も減衰へ影響します。2025年の液滴振動研究でも、固体表面上の液滴の減衰が濡れ性によって変わることが扱われています。citeturn19search6turn19search3

したがってPURAでも、

**「Spring Strength = 0.8」だけでゼリー感を決める**

のではなく、

**復元の速さ・減衰・接地・慣性・サイズ依存性**

を一つの材質としてまとめて調整する方が、本物感が出やすいはずです。

## 一滴だけで確認すべきリアリティ項目

ここが今回の中心です。

以下は、**一滴だけを置いたMaterial Study段階で潰すべき項目**です。

まず融合は忘れて構いません。

このチェックだけで「触っていたい一滴」になることを目標にします。

### 静止状態と形

液体は動いていなくても、その形から材質を推測されます。静止した液体形状だけでも人が液体らしさを判断できることが報告されているため、休止形状は軽視できません。citeturn17search2turn22search1

| ID | 確認項目 | 合格の見方 |
|---|---|---|
| S01 | **完全な球になりすぎていないか** | 床側だけ自然に少し扁平になっている |
| S02 | **接地面が存在するか** | 点で置かれたビー玉ではなく、弱い接触面を感じる |
| S03 | **接地部分の曲率が滑らかか** | 球と平面を単純に切ったような段差がない |
| S04 | **上面と底面の形に差があるか** | 重力と接地を感じる |
| S05 | **サイズが大きくなるほど少し平たくなるか** | 全サイズが相似球ではない |
| S06 | **体積が一定に見えるか** | 潰れたときに物質が消えたり増えたりしない |
| S07 | **横に広がると高さが減るか** | squashだけして体積が増えない |
| S08 | **静止後に完全に安定するか** | 永久に微振動しない |
| S09 | **輪郭に不自然な角がないか** | 全方向に滑らかな曲率 |
| S10 | **左右対称すぎないか** | 動作直後にはわずかな履歴が残る |
| S11 | **影が本体形状と一致しているか** | 浮いて見えない |
| S12 | **接地時の色密度が自然か** | 底だけ不自然に黒くならない |
| S13 | **小滴と大滴で“同じ材質”に見えるか** | サイズを変えても別物質化しない |
| S14 | **シルエットだけでも柔らかそうか** | opaque表示にしても硬い球に見えない |
| S15 | **停止画だけでも水滴／液体候補に見えるか** | シェーダー頼みになっていない |

特に**S14は非常に有効な開発テスト**です。

いったん透明マテリアルを外し、

> 灰色の粘土のようなopaque材質にする。

それでも動かしたとき、

> 「これは柔らかいものだ」

と感じるか。

感じなければ、屈折を増やす前に形と変形を直すべきです。

### 指でつかんだ瞬間

直接操作では遅延が操作成績・知覚に影響し、低遅延化の研究が長く行われています。Appleもタッチ予測を「入力と画面描画の見かけの遅延を減らす」手段として提供しています。したがってPURAでは、柔らかさを演出するために**入力そのものを遅らせる**のは避けるべきです。citeturn20search1turn20search2turn20search6

| ID | 確認項目 | 合格の見方 |
|---|---|---|
| T01 | **触れた瞬間に反応するか** | 「掴めた」と即座に分かる |
| T02 | **掴んだ地点が指に追従するか** | 本体全体を遅らせず、接触点は直接的 |
| T03 | **周囲の形だけが少し遅れてついてくるか** | direct controlと柔らかさを両立 |
| T04 | **引いた方向へ局所的に伸びるか** | 全体が均等拡大しない |
| T05 | **伸びた分だけ横幅・高さが変わるか** | 体積保存感がある |
| T06 | **反対側に慣性の遅れがあるか** | 頭と尻尾が完全同期しない |
| T07 | **ゆっくり引く場合と速く引く場合で変形量が違うか** | 速度情報が材質へ反映される |
| T08 | **つかんだ位置で反応が変わるか** | 中心・縁の操作が完全同一でない |
| T09 | **突然つかんでも破綻しないか** | メッシュの跳び・反転がない |
| T10 | **指の下に隠れても位置を把握できるか** | スマホでも操作点を失わない |

ここで非常に大事なのは、

> **指には速く、物体内部には少し遅く反応させる**

ことです。

ユーザーの入力を0.1秒遅らせれば「柔らかい」わけではありません。

**制御点は即応し、質量がその後からついてくる。**

この因果関係の方が、PURAの「触っている」感には合うと考えます。

### 離した瞬間と滑走

| ID | 確認項目 | 合格の見方 |
|---|---|---|
| M01 | **指の離し速度が初速へ自然に変換されるか** | 同じフリックは概ね同じ結果になる |
| M02 | **離した瞬間に速度が飛ばないか** | drag→releaseが連続している |
| M03 | **進行方向へ少し伸びるか** | 高速ほど形がわずかに長くなる |
| M04 | **後端に遅れが生じるか** | rigid-bodyの球に見えない |
| M05 | **加速後に一度オーバーシュートするか** | 弾性の存在を感じる |
| M06 | **横方向にも反作用が出るか** | 単純なX方向scaleだけでない |
| M07 | **滑走中も接地しているか** | 一瞬浮遊して見えない |
| M08 | **低摩擦だが無摩擦ではないか** | ゆっくりエネルギーを失う |
| M09 | **減速曲線が機械的すぎないか** | 毎フレーム同率減速だけに見えない |
| M10 | **停止直前が不自然にスナップしないか** | 速度が滑らかに消える |
| M11 | **サイズによって慣性感が変わるか** | 大滴と小滴が全く同じ動きでない |
| M12 | **高速でも輪郭が破綻しないか** | 伸びすぎ・尖りすぎがない |
| M13 | **速度変化と屈折変化が同時に起こるか** | 形だけ動いて内部像が遅れない |
| M14 | **停止後に余韻があるか** | 一度程度の大きな戻り＋弱い減衰 |
| M15 | **余韻が長すぎないか** | ゼリートイではなく上質な液体に留まる |

「氷の上を滑る」感を優先するなら、現実の接触線摩擦をそのまま再現する必要はありません。ただし、**完全無摩擦のCG球にもしてはいけません**。実液滴の接触線には静的・動的な抵抗があるため、PURAではこれをごく弱く美化して残すと「表面を滑っている」という接触感が出るはずです。これは物理研究からのゲーム設計上の推論です。citeturn19academia18

### ぷるんぷるんとした弾力性

ここは「ある／ない」だけでは不十分です。

| ID | 確認項目 | 合格の見方 |
|---|---|---|
| E01 | **変形後に元へ戻ろうとするか** | 明確な復元力を感じる |
| E02 | **一度で戻らず少し行き過ぎるか** | 質量＋弾性を感じる |
| E03 | **振動周期が自然か** | バネ玩具の高速振動に見えない |
| E04 | **振幅が毎周期減るか** | エネルギーが自然に散逸する |
| E05 | **減衰しすぎないか** | ただの粘土にならない |
| E06 | **減衰が弱すぎないか** | 永久ゼリーにならない |
| E07 | **大きさで振動感が変わるか** | 全滴が同じ周期でない |
| E08 | **変形方向と揺れ方向がつながるか** | 横衝撃なのに上下だけ揺れない |
| E09 | **複数方向の変形モードがあるか** | scaleX↔scaleYだけでない |
| E10 | **表面に弱い波が伝わるか** | 衝撃点から応答が広がる |
| E11 | **底面は上面より拘束されているか** | 空中ゼリーのように全体自由でない |
| E12 | **静止状態では揺れないか** | 小さな数値誤差を視覚化しない |

液滴の振動は、表面張力による復元と粘性散逸による減衰を持つため、**「振動の周波数」と「減衰の速さ」は別パラメータとして扱うべき**です。また、固体表面に置かれた滴では濡れ性や接触線も振動モードに影響します。citeturn19search6turn19academia18

ここはCodexにも明確に、

> `stiffness` 一個で全部決めない。

と伝えてよいと思います。

## 滑走・衝突・融合で確認すべき項目

一滴が成立した後、PURA FLOWの本領はここです。

実際の液滴衝突では、相対速度、滴径、表面張力、粘性、衝突位置などによって、融合だけでなくバウンドや分裂まで結果が変わります。古典的なQian & Lawの実験では、衝突Weber数とimpact parameterによって衝突結果を整理できることが示されています。後続研究でも同様に、Weber数と衝突位置が主要因として用いられています。citeturn18search1turn18search13

PURAでは同色ならゲームルール上**融合を優先**して構いません。

ただし、融合結果を強制しても、

**融合までの0.2〜1秒程度の“身体表現”は、速度と角度に応じて変える**

べきです。

これが、物理シミュレーターになりすぎず、本物感だけを借りる方法です。

### 壁・他物体への衝突

| ID | 確認項目 | 合格の見方 |
|---|---|---|
| C01 | **接触直前まで連続的に動くか** | collision snapがない |
| C02 | **当たった場所から潰れるか** | 全体を瞬時にscaleしない |
| C03 | **正面衝突ほど大きく潰れるか** | 衝突速度との関係が読める |
| C04 | **かすり衝突では斜めに変形するか** | head-onと同じ演出ではない |
| C05 | **接線方向の速度が残るか** | 壁に触れただけで全停止しない |
| C06 | **圧縮後に反動があるか** | 柔らかさを感じる |
| C07 | **反発しすぎないか** | スーパーボール化しない |
| C08 | **衝撃波／揺れが接触点から広がるか** | 全頂点同時反応を避ける |
| C09 | **高速衝突ほど余韻が大きいか** | 入力エネルギーとの対応がある |
| C10 | **低速接触では静かか** | 毎回派手なぷるんにしない |

### 二滴の融合

ここはPURA FLOWの「必殺技」です。

| ID | 確認項目 | 合格の見方 |
|---|---|---|
| F01 | **最初の接触位置が見えるか** | 瞬時に一滴へ置換しない |
| F02 | **接触点に液体ブリッジができるか** | 二球の間に首が生まれる |
| F03 | **ブリッジが時間とともに太るか** | 「接着」ではなく「融合」に見える |
| F04 | **境界が徐々に失われるか** | 球同士が重なったまま残らない |
| F05 | **融合中に一度細長い形を通るか** | 二滴だった履歴を感じる |
| F06 | **最終体積が合計に見えるか** | 一滴が突然巨大化／縮小しない |
| F07 | **重心位置が自然か** | 大滴側へ適切に寄る |
| F08 | **運動量が自然に引き継がれるか** | 融合直後に方向が飛ばない |
| F09 | **正面融合と斜め融合で形が違うか** | 衝突履歴を残す |
| F10 | **高速ほど大きく変形するか** | 全衝突が同じアニメではない |
| F11 | **サイズ差で挙動が変わるか** | 小滴を大滴が“飲み込む”感じを出す |
| F12 | **融合後に表面波が走るか** | 質量追加の衝撃を感じる |
| F13 | **融合後に1〜数回だけ余韻があるか** | 「ぷるん」の報酬になる |
| F14 | **融合中も次の入力を受けるか** | animation lockしない |
| F15 | **融合途中でも次の滴を吸収できるか** | PURAの連鎖快感を守る |
| F16 | **三滴同時付近でも破綻しないか** | topology popがない |
| F17 | **高速で通り抜けないか** | tunnelingがない |
| F18 | **法線が突然反転しないか** | ハイライトが点滅しない |
| F19 | **屈折像が融合途中も連続しているか** | geometryとshaderが別世界にならない |
| F20 | **色が内部から連続的にまとまるか** | 単純な瞬間色切替を避ける |

実液滴の衝突では「融合」以外にも、バウンド、融合後の分離、引き伸ばされての分離など複数のレジームがあります。PURAではその結果自体を再現しなくても、**高速・斜め衝突ほど変形が非対称になる**という視覚的特徴は借りられます。citeturn18search1turn18search9turn18search13

特に重要なのは**F02〜F05**です。

二つの球体が触れた瞬間、

```text
sphere A + sphere B
↓
sphere A を消す
↓
big sphere C を出す
```

では、ゲームロジック上は融合でも、人間の目には**オブジェクト交換**に見えます。

欲しいのは、

## 光・屈折・透明感で確認すべき項目

PURAのスクリーンショットを見る限り、ここはすでにかなり強いです。

ただし透明材質は、少し間違えるだけで

**水 → ガラス → アクリル → 宝石 → 石鹸玉**

と材質カテゴリーが変わります。

Three.jsの現在の`MeshPhysicalMaterial`には、transmission、IOR、attenuationColor、dispersionなど、透明材質を作るためのパラメータがあります。また公式ドキュメント自身が、こうした高度な機能は通常マテリアルよりピクセル当たりの負荷が高いと説明しています。citeturn20search3

研究では、透明液体を知覚するうえで**動的な画像変形だけでも強い透明・液体手掛かりになる**ことが示されています。また透明ゼリーの弾性判断でも、輪郭運動と光学変形のパターンが使われます。citeturn17search0turn17search3

つまり、

> 水滴を潰したらシルエットだけ潰れて、  
> 中の屈折はほぼ同じ。

これはかなりもったいない。

逆に、

> 指で引く  
> → 表面曲率が変わる  
> → ハイライトが長く伸びる  
> → 背景像もその場所だけ引き延ばされる  
> → 離す  
> → 表面が戻る  
> → 屈折像もぷるっと戻る

となると、**画面には触覚デバイスがないのに、「柔らかそう」という感覚をかなり作れます**。

これはPURA FLOWが狙うべき「視覚による触感」です。

### ガラス玉に見えてしまった時の診断順序

現在のスクリーンショットから今後特に注意したいところです。

「ガラスっぽい」と感じたときに、いきなりIORを変えるのではなく、

**まずこの順で確認**するとよいと思います。

| 順 | 確認するもの | 理由 |
|---|---|---|
| A | 接地部が平らになっているか | 完全球はビー玉感が強い |
| B | 移動時に形が崩れるか | 硬質物との差が最も出る |
| C | 停止時に減衰振動があるか | 弾性／液体性を示せる |
| D | 屈折像が変形と連動するか | 透明液体の強い知覚手掛かり |
| E | ハイライトが硬すぎないか | ガラス／クリスタル感の原因 |
| F | 内部色が表面色ではなく厚みで変わるか | 「色付きガラス塗装」を避ける |
| G | 色収差や極端な反射がないか | 宝石感を抑える |

**IOR調整だけでは「水滴らしさ」は完成しない**、というのがここでの重要なポイントです。

## 触って気持ちいいUXを確認する項目

PURAでは「正しく動く」と「気持ちよく動く」を分けて評価した方がよいです。

流体シミュレーションの知覚評価研究でも、数値手法の優劣だけでなく、**人が映像をどう評価するか**が独立した問題として研究されており、実写の参照動画を提示すると評価の一貫性が高まることが報告されています。citeturn21search2turn21academia29

PURAではさらに、物理的正確さとは別に**Pleasure**があります。

そこで一つの挙動につき、三軸で評価することを勧めます。

> **Plausibility — 本物っぽいか**
>
> **Pleasure — 気持ちいいか**
>
> **Control — 思い通りに扱えるか**

例えば、

| 状態 | Plausibility | Pleasure | Control | 判断 |
|---|---:|---:|---:|---|
| 本格流体だが予測不能 | 5 | 3 | 1 | ゲームには不向き |
| rigid sphereだが操作良好 | 2 | 3 | 5 | PURAには物足りない |
| 激しくぷるぷる | 3 | 4 | 3 | 玩具っぽくなりやすい |
| 少し誇張した液滴 | 4 | 5 | 5 | **PURA候補** |

### 直接操作のチェック

| ID | 確認項目 | 合格の見方 |
|---|---|---|
| U01 | **touch downで即座に反応するか** | 触れた感覚がある |
| U02 | **pointerから水滴が遅れて逃げないか** | latencyを柔らかさと混同しない |
| U03 | **指位置と掴み位置がずれないか** | direct manipulationを維持 |
| U04 | **遅れるのは質量側だけか** | 接触点は即応、胴体は追従 |
| U05 | **短いフリックと長いスワイプを区別できるか** | 意図が速度へ反映される |
| U06 | **弱い入力でも結果が見えるか** | 微操作が死んでいない |
| U07 | **強い入力を頭打ちにしすぎないか** | 熟練の余地を残す |
| U08 | **画面端でもつかみやすいか** | UI都合で操作不能にならない |
| U09 | **フレーム落ちで入力感が変わらないか** | physicsとrenderを整理する |
| U10 | **120Hz端末等で不自然に挙動が変わらないか** | timestep依存を防ぐ |
| U11 | **マウスとタッチで本質的体験が一致するか** | Web版の一貫性 |
| U12 | **指を離した瞬間に“手放した”感があるか** | release causal cueを作る |

直接タッチにおいて遅延が操作パフォーマンスへ影響することは実験的に調べられており、OS側も予測タッチを低遅延化に利用しています。PURAでは平均FPSだけではなく、**入力から画面上の変化までのend-to-end latencyを別に計測**する価値があります。citeturn20search1turn20search2

特に、

**60fps出ている = 操作が速い**

とは限りません。

イベント取得、シミュレーション、レンダリング、ブラウザ合成、ディスプレイ表示までを通した**指→光子**の遅れを見るべきです。

### 「触覚がないのに触感を感じる」ための設計

仮想物体について、人は形状情報だけから柔らかさを一貫して判断できることが示されています。さらに透明なゼリーでは動的な輪郭・光学変形から弾性を判断できるため、PURA FLOWは実際のフォースフィードバックがなくても、かなり強い擬似触感を作れる可能性があります。citeturn22search1turn17search3

私なら触感を次の因果チェーンにします。

**指を置く**

→ 接触箇所が1〜数フレームでわずかにへこむ

→ 反対側が少し遅れて移動する

→ ハイライトが伸びる

→ 背景屈折が引かれる

→ 指を離す

→ 形が少し行き過ぎる

→ 逆側へ戻る

→ 小さな揺れを1〜2回

→ 静止

これが一つの「触感文法」です。

同じように融合には、

**接触**

→ 軽い圧縮

→ 小さな液体ブリッジ

→ 一気に首が太る

→ 質量が移動

→ 全体が一度大きく変形

→ 内部像がぐにゃっと変わる

→ 低く短い音

→ ぷるん

→ 静止

という文法を与える。

ゲーム全体でこの因果を統一すると、**PURA Fluidには“物性の人格”が生まれます。**

## 開発陣が使うべき検証方法

ここまでのチェック項目は、感覚だけで調整すると途中で基準を失います。

PURA FLOWでは、**Reference Lab**を一つ作ることを勧めます。

流体シミュレーションの知覚評価研究では、慎重に選んだ現実の参照動画と比較することで評価の一貫性が改善しました。PURAでも同じ考え方を採用できます。citeturn21search2turn21academia29

### 実写を一種類だけ正解にしない

PURA Fluidは架空物質なので、参照映像も一物質に限定しません。

例えば、

| 参照したい性質 | 現実側の参考対象 |
|---|---|
| 光学 | 水滴、透明シリコーン、透明ゲル |
| 滑走 | 低濡れ性・撥水面上の滴 |
| ぷるん | 柔らかい透明ゲル |
| 衝突 | 液滴の高速撮影 |
| 融合 | 同種液滴のcoalescence |
| 落ち着き方 | 粘性の違う複数液体 |

つまり、

**「この物質を再現する」ではなく、「各現象の最高の部分を採取する」**。

そのうえで一貫したPURA Fluidへまとめます。

### 固定テストシーン

毎回同じ条件で録画して比較できるようにします。

| Test | シーン | 見るもの |
|---|---|---|
| R-A | 小滴を静置 | 接地形状、影、屈折 |
| R-B | 大滴を静置 | サイズ依存の扁平化 |
| R-C | 低速ドラッグ | 局所変形、追従 |
| R-D | 高速ドラッグ→release | 伸び、初速、揺れ |
| R-E | 自由滑走 | 摩擦、慣性、停止 |
| R-F | 壁へ低速正面衝突 | squash |
| R-G | 壁へ高速正面衝突 | overshoot、減衰 |
| R-H | 壁へ浅角衝突 | 接線速度、非対称変形 |
| R-I | 同サイズ二滴・低速融合 | bridge、自然な一体化 |
| R-J | 同サイズ二滴・高速融合 | 大変形と余韻 |
| R-K | 1:3サイズ融合 | 小滴の吸収感 |
| R-L | 斜め融合 | 非対称性 |
| R-M | 3滴連続融合 | 振動の継承 |
| R-N | 5滴連続融合 | PURA看板UX |

### 数値で残すもの

「なんとなく良くなった」だけではなく、最低限これをログ化すると強いです。

| 指標 | 意味 |
|---|---|
| 初速 | releaseの再現性 |
| 移動距離 | 滑走感 |
| 停止までの時間 | 摩擦／減衰 |
| 最大縦横比 | 変形量 |
| 第1オーバーシュート量 | 弾性 |
| 揺れ周期 | material identity |
| 揺れ半減時間 | damping |
| 接地幅 | wetting感 |

| 融合後最大変形量 | merge reward |
| 融合前後の体積誤差 | conservation |

| transparency overlap時負荷 | 描画限界 |

液滴衝突については、研究ではWeber数

\[
We=\frac{\rho U^2D}{\sigma}
\]

のように、慣性と表面張力の相対関係を使って衝突レジームを整理します。citeturn18search13

PURAで流体力学を厳密に再現する必要はありませんが、この考え方は実装設計に使えます。

つまり、

> **速度が2倍になっても変形がまったく同じ**

ではなく、

> **速度が増えるほど慣性優位になり、潰れ・伸び・揺れも大きくなる**

という関係を持たせる。

これは単発のアニメーションを再生するより、一段上の本物感につながります。

### 最も強力な「機能を切る」テスト

PURAでは以下のデバッグモードを用意すると、どこがリアルさを作っているか非常に分かりやすくなります。

| Debug Mode | OFFにするもの | 問うこと |
|---|---|---|
| **Clay** | 透明・屈折・色 | 動きだけでも柔らかいか |
| **Freeze Shape** | 変形 | shaderだけではガラス球にならないか |
| **No Refraction** | 背景屈折 | 屈折が本当に効果を出しているか |
| **No Highlight** | specular | ハイライト依存になっていないか |
| **No Jiggle** | 弾性振動 | 何が失われるか |
| **No Audio** | 効果音 | 映像だけで融合が気持ちいいか |
| **Slow Motion** | 時間を1/4へ | topology jumpや破綻がないか |
| **Wireframe** | 表面描画 | geometryの品質 |
| **Volume View** | 通常描画 | 体積保存 |
| **Latency View** | 通常UI | touch eventとrender反映時刻 |

これらはかなり重要です。

**最高の水滴shaderを作ってから動きを直す**のではなく、

> Clayでも気持ちいい  
> ↓  
> Transparentにするとさらにいい  
> ↓  
> Refractionを入れると「本物だ」と感じる

という積層構造を目指すべきです。
