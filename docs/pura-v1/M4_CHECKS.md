# M4の仕上げ確認 — 60個の長時間と、スマホ計測（2026-09-26）

## 60個・10分の連続操作

自由モード60個・三色・押し込み混色。GPU描画のヘッドレスChrome（Apple M1、390×844）。無作為に投げる219・押し込み93・2回タップ93・盤面をなぞってまとめる56、並べ直し17回（60秒ごと／6個未満で）。融合1,007回・分離14回。`artifacts/m4/sixty-drop-ten-minute-soak.json`

- 例外・警告0、掴みっぱなし0、色の総量の誤差0。
- 描画資源は滴の数に合わせて増減し蓄積なし（テクスチャ4・プログラム9で一定）。JSヒープ39〜118 MBで増加傾向なし。
- ただし大量の融合が重なる瞬間にコマ間隔が33〜67 msに伸びる引っかかりを確認 → 下記で改善。

## 連続融合の引っかかりの改善

60個1色を盤面ごとなぞってまとめる操作（画面同期なしで実コストを計測、3回平均）:

| | 改善前 | 改善後 |
|---|---:|---:|
| コマ間隔の中央値 | 約13 ms | 約8 ms |
| p95 | 約33 ms | 22〜25 ms |
| 最大 | 120〜170 ms | 約34 ms |
| 33 ms超 | 13〜25回 | 1〜3回 |

CPUプロファイルで原因を特定して順に対処（見た目は公開版と画素差0を3画面で確認）:

1. 融合途中の表面計算（マーチングキューブ）: 距離計算を `Math.hypot` から平方根へ、滑らかな結合の平坦な場合を省略。小さな雫は格子を粗く（半径50以上40³、30以上32³、それ未満24³）。格子を使い回すプール。1コマの表面更新を6個までに制限し、見送った雫は前回の形で描画と光路をそろえる。未構築の最初のコマは丸い雫で表示。
2. GPUへの転送: 表面の更新で確保済み最大18000三角形分を毎回送っていたのを、描画する分だけに（`addUpdateRange`）。外接球の毎フレーム全走査をやめ、既知の大きさから設定。
3. 大きな雫が小さな雫（結果の12%未満）を吸い込むときは融合途中の表面を作らない（形の差は見えず、なぞる操作の大半を占める）。同程度の大きさの融合（3面・入口プレイの承認済みの見た目）は従来どおり。
4. 床の影・光の模様・しぶき・床光の点のマテリアルはトーンマッピングの処理を含まないため `toneMapped: false` に。背景撮影と画面描画でプログラムが毎回切り替わるのを防ぐ（見た目は不変）。

残りは主にGPUの描画待ち（60個の透明な雫の屈折描画そのもの）。スマホ実機の数値を見て画質との兼ね合いを判断する。融合ごとのマテリアル新規作成（約1割）は未対処。

## iPhoneの実測（2026-09-26）

ユーザーのiPhone（iOS 18.7のUA、Safari、DPR3、402×874）で `?play=bench`。`artifacts/m4/iphone-bench-20260926.json`

| 個数 | 美しさ優先（1.75×） | 軽さ優先（1×） |
|---:|---|---|
| 12 | 59 fps・中央値17・p95 17 | 59 fps |
| 24 | 59 fps・17・17 | 59 fps・17・17 |
| 60 | **42 fps・24・28**（33 ms超2回） | 59 fps・17・18 |

表示まで1.6秒（通信条件は未統制の参考値。P-04の暫定3秒以内）。12個・軽さ優先の行は記録コマが61と少なく、計測中に一時的に非表示になったと考えられるため判断に使わない。

判断: 12〜24個（入口プレイ・三つの道・第1〜3・5面）は美しさ優先で余裕。36〜60個（第4・6〜8面、サンドボックス、自由モード）で60 fpsを割り得る。一律に軽さ優先へ落とさず、美しさ優先に自動の解像度調整を入れた。

## 自動の解像度調整

`src/experiments/fusion-lab/adaptive-resolution.ts`。美しさ優先のときだけ、1秒ごとのコマ間隔の中央値が19 msを超えたら描画倍率を1.75→1.5→1.25→1.0と1段ずつ下げ（2秒の待ち）、中央値17.4 ms以下・p95 19 ms以下が続いたら1段ずつ戻す（戻した直後に遅れたら次の戻しまでの待ちを倍に、最大32秒）。

- 30 Hz表示や省電力モードの33 ms間隔では下げない。ただし60 Hz画面では処理が間に合わないコマも33.3 msに揃うため、1コマの処理時間（シミュレーション＋描画命令）の中央値が8 ms未満のときだけ「画面側の上限」と判断する。
- 描画倍率だけを変え、盤面の大きさ・つかんでいる雫・物理には触れない。読み込み直後の3秒は判断しない。軽さ優先は固定の1×。
- 検証: 判断のテスト6件。ブラウザで描画命令ごとに0.1 msの負荷を加えると約8秒で1.75→1.0へ、負荷を外すと約18秒で1.75へ戻ることを確認。通常の見た目は公開版と画素差0（第3面・入口プレイ）。計測ページに「60個・自動」の行を追加（慣らし7秒）。
- 未検証: iPhoneで60個を自動調整にしたときの実測（計測ページの7行目で確認できる）。
