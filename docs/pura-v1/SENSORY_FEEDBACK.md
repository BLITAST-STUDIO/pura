## 2. ゲーム面の壁の手応え

- 以前は融合／3面の描画で壁の衝撃が常に0に固定され、M1で承認された「壁で潰れて戻る」反応が起きていなかった。
- `PuraSim.onContact` を追加。壁・固定石・滴同士の跳ね返りで実際に加わった速度変化を観測者へ渡すだけで、物理の結果は観測の有無でビット単位に一致（テストで確認）。リサイズや分離時の位置補正は接触として報告しない。
- `FusionSimulation.contacts` が1フレーム分を保持し（上限512件）、描画側が滴ごとに合算して共有の `DropletMotion` へ渡す。M1の `DropletSimulation.wallImpulse` と同じ量になることを1%以内で確認（差はM1側が同じ段の0.8%減衰も数えるため）。
- 固定石にも同じ反応が出る。石の形に沿って潰れる変形は未実装（提案3の範囲）。

## 1. 音と振動

音声ファイルは使わず、Web Audioで毎回合成する。容量増加なし。

| 出来事 | 音 | 振動 |
| --- | --- | --- |
| つかむ | 小さな上向きの泡音「ぷ」＋こもった接触音 | 8 ms |
| 壁・石に当たる | 低い「とっ」。石は少し硬い高域を足す | 衝撃に応じ5〜18 ms |
| 融合 | 音程が上がる水滴の「とぷん」。純色は澄んだ余韻、混色は濁ったうなり | 純色1回／混色2回 |
| 純度を保って全部集めた | ガラス鈴1音 | 10 ms |
| 輪に届いた | 2音。全目標達成は4音の分散和音 | 2〜3回 |
| 一手戻す | 短い巻き戻し音 | 6 ms |

- 音程は滴の大きさ（大きいほど低い）、左右の定位は盤面上の位置に従う。色ごとに鈴の高さが違う（シアン784 Hz、ローズ659 Hz）。
- 壁へ押し付け続ける間は毎段で接触が起きるため、0.12秒以上静かだった後の最初の接触だけを「衝突」として鳴らす。弱い接触（速度変化70未満）は鳴らさない。
- 軽い部屋の残響と、同時多発時の音割れを防ぐリミッターを通す。
- 振動: Androidなどタッチ端末のVibration API。iPhoneのSafariには同APIがないため、iOS 18以降で知られる非表示スイッチ部品のクリックによるシステム触覚を試す（強さ固定・ユーザー操作の中でのみ働く可能性）。**実機未検証**。PCでは振動設定を表示しない。
- 設定: 3面は操作列のスピーカーボタンと「遊び方と表示」、実験画面は設定パネルに「音」「振動」。ブラウザごとに `pura-flow-sensory-v1` へ保存。`?sound=off` / `?haptics=off` はその訪問だけ消音。
- iPhoneはマナーモード（消音スイッチ）中はWeb Audioが鳴らない。最初のタッチでは音声の起動が間に合わず、1回目のつかむ音が鳴らない場合がある。

## iPhoneで鳴らない報告（2026-09-25）

ユーザー報告: PCでは聞こえるがiPhoneで聞こえない。原因候補は (1) 消音スイッチ（Safariは消音中にWeb Audioを鳴らさない）、(2) 音声起動の取りこぼし。(2)を修正: 状態が `suspended` 以外（iOSの `interrupted` など）でも、操作のたびに再開する。最初の操作の中で無音を1回鳴らし、古いiOSでも出力を有効にする。実機での確認はユーザー待ち。(1)の場合に消音スイッチを無視して鳴らすか（`navigator.audioSession`）はユーザー判断。


## 音が出ないときがある（2026-09-27）

ユーザー: 「たまに音が出てないときがある？色の分離ではじいた瞬間から音が開始することがありそう」。

- 原因（推定、実機未確認）: iPhoneのSafariは、軽いタップを「音を始めてよい操作」とみなし、指を引きずる操作はみなさない。PURAの操作はほとんどがドラッグ（つかんで動かす、引いて離す）なので、タップせずに遊び始めると音が止まったままになる。色の分離はすばやい2回タップなので、そこで初めて音が始まる。電話や他のアプリで音が中断されたあとも、タップまで同じ。
- 対策:
  1. 音を始める試みを、指を置いた瞬間（touchstart）とクリックにも広げた（以前は pointerdown・pointerup・touchend・keydown）。
  2. 古いiOS向けの「無音を一度鳴らして出口を開ける」処理を、最初の1回だけでなく、音が動き出すまで毎回試すようにした。
  3. それでも止まっていたら、盤面に小さく「♪ タップで音をオン」（音がオンで、盤面に触れたあと、0.7秒たっても止まったままのときだけ）。押すと始まり、動き出せば自動で消える。消音の設定や、消音スイッチの判断（2026-09-25 のユーザー決定）は変えていない。
- 検証: ヘッドレスChromeで、iPhoneのように「タップまで止まったまま」の状態を作り、ドラッグのあとに表示が出る → 押すと音が動き出し表示が消えることを確認（`artifacts/sensory/sound-nudge.png`）。普通に音が出る場合は表示が出ない。表示の条件はテスト。実機のiPhoneでの確認は未。
- 実機（iPhone、2026-09-27）: ユーザーが「タップで音をオンを押したらすぐに音が出た」。表示が出たこと自体が、ドラッグや指を置いた瞬間では音が始まらないという見立てを裏づける。表示を押すタップで確実に始まる。
