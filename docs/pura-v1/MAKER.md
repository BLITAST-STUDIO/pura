# 自分のひとふで — 小さな台エディター

2026-10-01。ユーザーの「自作台を作り、友人に遊んでもらう」「自身でクリアできたもののみ共有する」という案を受け、単色ひとふでの配置・テストプレイ・共有リンクに絞った試作。作る楽しさと、受け取って遊ぶ楽しさを確認する。無料の入口を保ち、制作を完全版の価値にする案は候補であり、課金・販売範囲の決定ではない。

入口: https://blitast-studio.github.io/pura/next/?play=maker 。作業ブランチ `feat/hitofude-maker`。身内版ルートは更新せず、mainにも未統合。

## できること

- 固定の420×560の盤面に単色の雫を2〜12個、固定石を0〜8個（2026-10-02に3個から）置く。雫・石とも大きさは3種類。盤面・壁・摩擦・融合ルールは編集しない。
- 雫や石を選び、指で動かす。数値位置指定と矢印キーも使える。重なりや盤面外の配置は防ぐ。配置の一手戻すは40回まで。
- 名前を付け、配置をこのブラウザに自動保存する。専用キー `pura-flow-maker-draft-v1` を使用。保存できない場合は表示する。初期配置は公式1番を基にした、解ける台。
- 「遊んで確かめる」で最初の配置からテストプレイ。最大12打、雫が止まってから次の一打。編集へ戻ると初期配置が残る。
- クリアを再生確認できた配置だけ共有リンクを作れる。配置・大きさ・数の変更後は再クリアが必要。名前だけの変更は有効。下書きにはクリア記録を保存せず、再読み込みしたら改めてクリアする。
- リンクを開いた人は、その台で直ちに挑戦できる。作者の打数が見え、何度でもやり直せる。友人の台を開いても自分の下書きを上書きしない。同じタブで別の台のリンクを開いた場合も切り替わる。

## 共有と再現性

共有リンクのフラグメント `#stage=...` に、版番号・初期配置・クリア時の打撃列を含める。ログインやサーバーへのアップロードは不要。作者側も受け取り側も、独立した物理シミュレーションで実際にクリアできることを確認する。「クリア済み」という自己申告だけでは受け付けない。

既存のひとふでの物理を継承し、メーカー内だけ1/120秒の固定刻み、静止後の打撃、引き幅の0.1単位化を採用してフレームレートの違いによる再現のずれを抑えた。既存コースの時間刻みやルールは変更しない。処理量を制限するためリンクは4096文字、打撃は12回、各打撃の再生は最大12秒。版1以外は明示的な回復画面へ。将来物理を変える場合は既存リンクへの対応を別途設計する。

端末の共有シート／コピーから、ユーザー自身がリンクを渡す。アプリはメッセージを自動送信しない。作成・受け取りに料金やアカウントは不要。作者本人の証明、公開作品一覧、サーバーへの投稿、購入権利は未実装。投稿型にする場合はサーバー側の再生検証・作品保存と管理を追加する。

## 連続して打てるように（2026-10-02）

ユーザー:「自作ひとふでで、エディットして試すとき、ひとつめをはじいたあと、ふたつめ以降を、ひとつめの雫の動きが終わる前でも好きなタイミングで打てるようにしたい。直感的に次のものも動かせるように（通常盤ではなかった挙動かも）」。作業ブランチ `feat/maker-chain`。

### 原因

- 自作ひとふでの `grab`（雫をつかむ処理）に「盤面の雫がすべて止まっているときだけ」という条件があった（Codex の実装）。共有リンクの検証が「毎回、静止状態から次の一打」を前提に作られていたため。
- ひとふでの雫は、ゆっくり滑る時間が長い（6〜7秒）。実ブラウザで確かめたところ、2発目のドラッグは無視され、5秒後も「雫が止まるまで待ってね」のままだった。
- **通常のひとふで（18ホール）は、この制限がない**: 条件は「つかむ雫が止まっているか（秒速30未満）」だけで、ほかの雫が動いていても別の雫を打てる。自作ひとふでだけの挙動だった。

### 直し方

- つかめる条件を通常のひとふでと同じに（つかむ雫が止まっていればよい。動いている雫そのものはつかめない）。「止まるまで待ってね」の表示を削除。
- 共有リンクの検証を、打つタイミングを記録する形（版2）にした。各打に、つかんだ刻み `g` と離した刻み `r`（固定の物理の刻み 1/120 秒を、開始から数えた回数）を入れる。検証側が同じ刻みで再現するので、フレームの速さ（30・60・120・144Hz）に関係なく同じ結果になる。
- 版1のリンク（試作で数日だけ作れたもの、刻みなし）も、静止状態から打つ形で引き続き開ける。刻みのない版2のリンクは拒否する。
- 悪用への備え: 刻みは整数で前に進むだけ（つかむのは前の離しより前にならない、離すのはつかむより前にならない）、全体で約3分（18,000刻み）まで。上限を超える偽の記録は即座に拒否（0ミリ秒）。

### 検証

- 型検査・189テスト（動いている最中に別の雫がつかめる・動いている雫自体はつかめない、重なり打ちの記録がフレームの速さ（120・60・30Hz）に依らず同一で再現できる、刻みの不正・版の違い・クリアにならない打撃列の拒否、版1のリンクが開く）。
- 乱数での負荷確認: ばらばらのフレーム時間・待ち時間・狙いで600回遊ばせ、クリアした307回（うち300回が重なり打ち）の記録がすべて検証を通った。不一致0、検証の最大は3.8ミリ秒。
- ブラウザ（GPU、スマホ幅、実際のポインター操作）:
  - 直す前（公開 `/next/`）: 1発目を離して150ミリ秒後に2発目をドラッグしても無視（「1/12打」のまま、「止まるまで待ってね」）。
  - 直した後: 同じ操作で2発目が打てて、さらに最後の一打でクリア（3打）、共有リンク（版2、431文字）が使える。そのリンクを友人側で開くと「作者記録 3打」、同じ台を重なり打ちでクリアして「ひとつに3打 · 作者と同じ」。警告エラー0。画像 `artifacts/maker/chain-author.png`・`chain-friend.png`。
- 直感的さについて: 動いている雫を直接さわるのは打てないが、止まっている別の雫を直接さわれば打てる。空いた床から引く操作は、選択中の雫が動いている間は反応しない（通常のひとふでと同じ）。
- 未確認: 実機での打ち心地。

## 盤の色（2026-10-02）

ユーザー:「自作ひとふでに、盤のカラーを選べるように。パステルカラーで何色かでも」。作業ブランチ `feat/maker-tone`。

- 編集画面の「盤の色」に、丸い見本7つ: 白（既定）・ミント・さくら・ラベンダー・レモン・そら・ピーチ。選ぶとすぐ盤の床の色が変わる。
- 色は**台の一部**: 端末の下書きに保存され、共有リンクにも載る（友人が開くと同じ色）。リンクが長くなるのは色を選んだときだけ（白は何も足さない）。色を持たない昔のリンクは白で開く。
- **色はクリアの確認に影響しない**: 色は物理と無関係なので、クリア済みの台の色を変えても「確認済み」のまま共有できる（`geometryKey` に含めない）。「一手戻す」で前の色に戻る。
- 友人側（挑戦の画面）には色の選択は出さない（作者の色で遊ぶ）。
- 仕組み: 描画エンジンに、床と周りの色を上書きする `tone` オプションを追加（自作ひとふで以外は使わない）。
- 色の決め方: 床は柔らかい照明で、見た目が「指定した色×約0.4＋107」のほぼ直線になる（実測、誤差1以内）。そのまま淡い色を指定すると灰色がくすむので、見た目がパステルになるよう逆算した指定色にした。実測した見た目: ミント (188,211,199)、さくら (207,184,198)、ラベンダー (193,189,211)、レモン (208,205,166)、そら (178,203,212)、ピーチ (207,191,166)。もとの白は (197,200,197)。床の見た目は最大でも約210までなので、色の濃さには上限がある（この範囲で淡く見えるものを選んだ）。
- 雫は透明なので、床の色が透けて見える。さくらでは青紫がかり、レモン・ピーチでは緑がかって見える（水の性質どおり）。シアンの雫をはっきり見せたいなら、白・ミント・そらが見やすい。

### 検証

- 型検査・191テスト（7色、白は既定で保存しない、未知の色は白に戻る、クリアの確認の対象外、共有リンクと下書きが色を運ぶ、昔のリンクは白）。
- ブラウザ（GPU、スマホ幅、実際のポインター操作、見た目の色は実際のスクリーンショットから測定）: 色の選択 → 遊ぶ（同じ色）→ 3打でクリア → 編集に戻って別の色を選んでも共有ボタンは有効 → 一手戻すで前の色 → 共有リンク（リンク内の色は選んだ色）→ 友人側で同じ色、「作者記録 3打」、色の選択は出ない。警告エラー0。画像 `artifacts/maker/tones.png`（7色の一覧）、`artifacts/maker/tone-editor-mint.png`。
- 未確認: 実機での見え方（画面の明るさや色の設定で変わる）。

## 石の形（2026-10-02）

ユーザー:「より戦略的なステージをユーザーに作ってもらうために、配置できる石（障害物）の形状をいくつか用意できないか。最低で三角形、四角形など」。作業ブランチ `feat/maker-shapes`（`feat/maker-tone` の上）。

### できること

- 石の形は4種: **丸**（これまで）・**三角**・**四角**・**六角**。大きさは小・中・大（外接円の半径 24・32・40）。
- 置くとき: 「石」を選ぶと「石の形」の行が出る。形を選んでから床をタップ。置いたあとに形を変える・向きを回す（「石を回す」、15°ずつ）こともできる。**置くモードのときは次に置く石の形だけが変わり、すでにある石は変わらない**。
- 向きは雫の通り道を変える重要な要素: 三角は先を上に、四角は面を縦横に揃えて始まり、回すと斜めの面ができる。四角は90°、三角は120°、六角は60°で元の形に戻るので、角度はその範囲に収める（四角は 45→60→75→0）。
- 形も台の一部: 下書き・共有リンクに載り、友人側でも同じ形。**形を変えると台の中身が変わる**ので、色（盤の色）と違い、クリアの確認はやり直しになる。一手戻すで戻る。

### 物理

- 雫は、石の面や角に当たると、壁と同じ反発（反発係数は丸い石・壁と同じ）で跳ね返る。斜めの面では、鏡の角度で曲がる。角に当たれば角から離れる向きに。
- 計算: 雫（円）と凸多角形の最短距離。雫の中心が多角形の外なら、最も近い点（面か角）から押し出し、内側に入ってしまったら、いちばん近い面から押し出す。丸い石の計算は**これまでと数式まで同じ**（既存の全ホールの再現テストがそのまま通る）。
- 台の入力の検査（共有リンクを含む）: 辺の数は 3・4・6 だけ、角度は15°刻みで範囲内の整数だけ。それ以外のリンクは開けない。ほかの雫・石・壁との間隔の検査は、多角形の外接円で行う（少し余裕を見た形）。
- 共有リンクの検証版 `MAKER_ENGINE` は 2 のまま。丸い石だけの台の物理は変わらず、多角形の台はこの試作で初めて作れるようになったため。公開後に多角形の物理を変える場合は版を上げる。

### 描画

- 丸い石は従来のドーム。多角形は、小さな面取りのある低い柱（角は物理の角と同じ位置）。色は同じ石の色。選択中の輪、持ち上げて動かす操作も同じ。

### 検証

- 型検査・198テスト（新しい5つ: 多角形の頂点と向き、面・角・内側の接触、雫が面で壁のように跳ね斜めの面で曲がる、300通りの乱数（辺・角度・大きさ・向き・速さ）で最深の食い込みが 1.5 未満、丸い石は従来どおり。台の側: 4種の形、辺と角度の厳密な検査、回転の繰り返し、形がクリアの確認の対象、移動しても形が残る、多角形の台が物理に届く）。
- ブラウザ（GPU、スマホ幅、実際のポインター操作）: 「石」→「四角」→床をタップ → 石を回す（45→60）→ 三角に変える→ 四角に戻す → 三角・六角を追加（置くモードでは既存の石は変わらない）→ 六角を回して一手戻す → 遊んでクリア → 共有リンク（形が載る、511文字）→ 友人側で同じ3つの石、「作者記録 1打」。警告エラー0。画像 `artifacts/maker/shapes-editor.png`・`shapes-friend.png`。
- 確認中に見つけて直した問題: 三角形の初期角度に270°を入れていたが、検査（120°未満）に反して三角形を置いた瞬間に台が無効になるところだった（30°が正しい）。形の行が「置くものを選ぶ」ボタンの上に出て、ボタンが指の下から動いていたので下に移した。遊ぶ画面の説明「雫が止まったら、次の一打」が連続打ちのあとは古くなっていたので直した。
- 未確認: 実機での置きやすさ、六角形など角の多い形が戦略として面白いか（遊んで評価）。

## オンボーディング（2026-10-02）

ユーザーの設計（二段構え、ユーザー自身がクリアした台だけがステージ、最後は白くフェードアウト）。作業ブランチ `feat/maker-onboarding`（`feat/maker-shapes` の上）。

### 第一段階: 何もない盤から

- 画面は盤だけ（ボタンや設定は一切出さない。右上に目立たない「とばす」のみ）。一行の言葉がふわっと現れる（ぼかしから浮かぶ）。
- 「自分だけの世界を、つくろう。」→「まずは、雫を3つ。好きな場所に、ふれて置く。」（丸い印3つが埋まっていく）→「次に、石を2つ。雫の行く手を、ふさいだり、導いたり。」（四角い印2つ）。大きさ・形・色は選べない（雫は中、石は丸の中）。近すぎる場所は「もう少し、離して。」。置いたものは指で動かせる。
- 「ためしてみましょう。」と「ためす」ボタン。ためす中は「配置しなおす」「やり直す」（打ち切りになったら「もう一度」が目立つ）。全部の雫がひとつになるまで次に進めない。
- クリアで光の輪と「あなただけの世界が、できました。」→「あなたのために、スタジオを用意しました。ここでは、もっといろいろなことができます。」→「スタジオへ」。
- この台はそのまま下書きになり、クリア済みとして引き継ぐ。以前の下書きがあれば「一手戻す」で戻せる（上書きで消えない）。

### 第二段階: スタジオの説明

- 編集画面に切り替わり、説明カード（7段、点で進み具合）。説明する部分を緑の輪で囲み、カードはその反対側（上か下）に出る。
  1. あなたのために、スタジオを用意しました。
  2. 雫と石を、置く。（置くものの選択）
  3. 大きさ、形、向き。（選んだものの調整）
  4. 盤の色も、選べます。
  5. **いちばん大切なこと。ステージになるのは、あなた自身がクリアした台だけ。クリアすると、ここが緑になります。**（クリアの印）
  6. 変えたら、もう一度クリア。台を変えると印は消えます。
  7. 緑の台は、友だちへ。（共有リンク）
- 最後に白が満ちて「これで説明は終わりです。あなただけのPURAを、つくってみてください。」、そのまま白く消えてスタジオへ（4.6秒）。「説明をとばす」もある。

### クリアの印（新しい）

- 編集画面の盤の右上に「未クリア」（灰色の点）／「クリア済み」（緑の点）。台を変えると灰色に戻る。
- クリアは端末に下書きと一緒に保存するようにした（これまでは開き直すと消えていた）。読み込むときは、その台で実際にクリアになるかを再生して確かめる（別の台や作り物の記録は無効）。

### 表示の条件

## 石を8個まで（2026-10-02）

ユーザー:「石の配置制限、もう少し増やしてみますか」。3個から**8個**へ（雫は12個のまま）。作業ブランチ `feat/maker-more-stones`（`feat/sound-popover` の上）。

- 8個にした理由: 盤（420×560、石は外接円の半径24〜40）に、雫の通り道を残したまま戦略的に並べられる数。雫の通り道は石どうしの間隔（最小8）の検査で保たれ、通れない配置になってもクリアできない台は共有できない（クリア済みの台だけが共有可能）。さらに増やすのは数字一つ（`MAX_STONES`）で、その前に下の確認をやり直す。
- 確認した点（増やす前に）:
  - 共有リンクの長さ: 最大構成（雫12・六角の石8・32文字の名前・色・12打の記録で刻みが大きい場合）でも上限4096文字に対して余裕（テストで確認）。実際に8個の台のリンクは727文字。
  - 物理: 形の違う石8個（丸・三角・四角・六角、大きさ・向き・速さを変えた乱数）で、雫が石の中にめり込まない（最も深い食い込み2未満）。
  - 描画: 編集画面の石の枠が3個分に固定されていた箇所を、設定できる数（`edit.slots`）に。
  - 既存: 3個以下の台・リンクはそのまま開く。オンボーディングは石2つのまま。
- 検証: 型検査・202テスト。ブラウザ（GPU、スマホ幅、実際のポインター操作）: 形を変えながら石を8個置く（表示「石 8/8」）、9個目は「石は8個まで置けます。」と断られる、遊んでクリア、共有リンク（727文字、石8個）、友人側で開いて「作者記録 1打」。警告エラー0。画像 `artifacts/maker/eight-stones.png`。
